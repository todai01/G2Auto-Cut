# GVox (G2Auto-Cut)

Настольная программа для записи и подготовки голосовых фраз IVR (банк, RU/KZ):
запись по таблице с суфлёром, нарезка, эталоны сумм и дат, аудит, сдача.
Python-бэкенд + веб-интерфейс в окне pywebview (Windows, WebView2).

## Как работать с пользователем

- Пишем по-русски. Интерфейс — строгий, минималистичный, без лишнего текста.
- После каждого законченного изменения: коммит → пуш в рабочую ветку → отправить
  пользователю **только изменённые файлы** (SendUserFile). Зип всего проекта — только по
  просьбе: `git archive --format=zip --prefix=G2Auto-Cut/ -o <scratchpad>/G2Auto-Cut.zip HEAD`.
  Готовая последовательность — скил `/ship`.
- Честно говорить, что проверено: песочница / демо-проект / браузер — не то же самое, что
  Windows + pywebview + Audacity + микрофон. Так и писать.
- Не придумывать новую механику там, где есть рабочая: запись — только через суфлёр Студии.
- Данные пользователя конфиденциальны (банк): не просить логины/пароли, не тащить реальные
  тексты/пути в коммиты, ролики и примеры. ИБ банка согласует автоматизацию и голосовые модели.
- PR не создавать без просьбы. Идентификаторы моделей в коммиты/код не писать.

## Устройство

- `main.py` — класс `Api` из миксинов `core/*` (все методы доступны JS как `pywebview.api.<имя>`).
  Каждый вызов из JS идёт в своём потоке → общее состояние меняется из нескольких потоков.
- `frontend/index.html`, `script.js` (~10 тыс. строк), `style.css`, `tutorial.js` (+ `tutorial/*.webm`).
  Python → JS: `webview.windows[0].evaluate_js(...)`, в Студии — `_tts_push(payload)` → `ttsProgress(p)`.
- Студия записи: `core/tts_flow.py` (состояние, дубли, ярусы, сборка, кэши),
  `core/tts_live.py` (запись, суфлёр, распознавание), `core/tts_synth.py` (синтез).
- Прослушка переменных: `core/listen_mode.py` + `frontend/listen.js` (папка записей → папка кусочков
  «Фразы_Переменные» с ru / kz, где отмечают начало и конец — пара своя на язык → таблица; запись ищется
  по имени, при папке с ru / kz — в своём языке; автосрезка по голосу `core/voice_trim.py` (вдох / шум
  по краям), шаблон срезки как в суфлёре — `.gvox_listen_tpl.json` в папке записей; Enter — сохранить и дальше;
  синтез голосом пресета через `_SynthWorker`). Таблица читается целиком — все столбцы (шапка `<firstname>` = подпись),
  ячейки идут по строкам слева направо; повтор имени (`rep`) слушается один раз. Левая панель — таблица-сетка
  (`.lg-cell`: зелёная — в «Готовые», фиолетовая — в «Исправить»). Сохранили — копия в `<папка записей>/Готовые/<столбец>/`,
  Backspace — в `Исправить/<столбец>/` (`_listen_file_to`); отмена — `listen_unfile`, Ctrl+Z — `lDecisions`.
- Студия — «только переменные»: таблица без листа фраз или с листом переменных (`<mark>` и т. п.), не названным
  в шапке фраз, читается; `tts_table_analysis` (что записано / новое) → выбор «Только переменные» (`tts_set_scope`,
  `st["vars_only"]`); свои начало и конец (аудиофайлы) для листа — `st["var_ctx"]`, подставляются в `_tts_var_chains`
  и `_tts_value_context`.
- «Два языка в одной записи» — кнопка в «Сборке» на дубль строки переменных (`tts_take_bil`, `t["bil"]`): ярусы
  удваиваются (RU, KZ, `_tts_tier_unit`), границы ставят вручную; файлы — `Значения/<лист>/<кат>/ru/<значение>.wav`
  и `…/kz/…` (`_tts_tier_path`), общий файл — в корзину. Готовность и аудит принимают пару ru + kz (`_tts_lang_done`).
- Отдельная программа «Прослушка» собирается из GVox скриптом `python tools/make_listen_project.py` (папка
  `dist/GVox-Listen`: только нужные файлы — `listen_mode`, `voice_trim`, `edit_basics`, `synth_browser`, `utils/*`, окно из
  кусков `index.html` между метками `<!-- @listen-app:… -->`; вход, сборка exe и README — `tools/listen_project/`).
  Общее вынесено, чтобы GVox и она делили код: `core/synth_browser.py` (синтез в браузере), `core/edit_basics.py`
  (правка «до правок», громкость), `utils/app_boot.py` (запуск окна, selftest), `frontend/ui_base.js` (окна, тосты).
  Прослушка перед первым синтезом спрашивает голос (`listen_voices` — имена с сервиса, `listen_set_voice`).
- Аудит: `core/project_handler.py` (`_audit_studio`), действия — `core/audit_fix.py`.
- Классика: `phrase_handler.py` (Excel, нарезка), `variables_handler.py` (суммы, пакетная сборка),
  `constructor_handler.py` (конструктор), утилиты — `converter.py`, `clone_prep.py`,
  `filename_match_handler.py`, `table_to_pptx_handler.py`.
- Синтез по таблице (утилита): `core/batch_synth.py` + окно `#bsynthOverlay` — Excel (шапка `<firstname>`…) →
  каждое значение готовым голосом по одному с паузой (строка за строкой, слева направо), спрашивает с какой строки
  и сколько; файлы `Синтез_<таблица>/<столбец>/<значение>.wav`, повтор значения — копия в `<столбец>_повторы(_2…)/`; голоса и языки — `SYNTH_PRESET_VOICES`, `SYNTH_LANGS`.
- `core/num_words.py` — числа словами RU/KZ, казахские месяцы, `month_abbr`.

## Предметная область

- Таблица Студии: лист фраз (`<phrase>`, `<name_phrase>`, флаги `<start>/<start_2>/<end>`) и
  листы переменных `<sum_ru>`, `<sum_kz>`, `<date_ru>`… «Фраза с переменной» = кусочки
  start / start_2 / end вокруг значения.
- Папки проекта: `Проверенные/` (цельные фразы), `Фразы_Переменные/` (кусочки),
  `Значения/<лист>/<категория>/<значение>.wav` (эталоны: `Значения/sum_kz/million_kz/5.wav`),
  служебные: `Записи/`, `Чанки/`, `_Корзина/`, `_Кэш/`, `.gvox_undo/`.
- Суммы читаются строкой, режутся на ярусы. Логика 1: миллионы + сотни + тысячи + тенге.
  Логика 2: отвечает **только** за «сотни тысяч» (100…900, 9 строк).
- Казахский: тысячи всегда «<число> мың» (бір мың); месяцы в KZ-листе показываются по-казахски.
- Аудит смотрит только `Проверенные`, `Фразы_Переменные`, `Значения` (корзина — никогда).

## Грабли, на которые уже наступали

- Не менять общее `st["sum_logic"]` даже временно — поток записи прочитает чужую логику
  (см. `_tts_logic_now`, thread-local).
- Опрос из JS не должен накладываться (`ttsRecPoll` с флагом занятости); тяжёлое в
  `tts_prompt_info` — кэшировать (`_tts_claims_cache`, `_tts_ver`).
- Распознавание пишет числа цифрами — `spell_digits` перед сравнением.
- Временные файлы прослушки — в системный temp, не в папки проекта (аудит их увидит).
- Фон под ярусами — сквозной по строке (`_tts_tier_audio` поверх `_tts_tier_dry`).

## Агенты — только для больших задач

`.claude/agents/`: `gvox-search` (Haiku, поиск по коду без правок), `gvox-check` (Sonnet, проверка на
демо-проекте по сценарию), `gvox-clips` (Sonnet, переснять ролики обучения, в фоне).
Звать только на больших задачах (новый режим, переделка экрана, много файлов + ролики).
Мелкие и средние правки — самому в основной сессии: агент стартует с нуля, это дольше и дороже.
План, ключевой код, проверка отчётов агентов, коммит и пуш — всегда в основной сессии.

## Проверка изменений

Windows здесь нет, поэтому проверяем на демо-проекте (`tools/demo/`, скил `/demo-check`):
- логика — Python: `from demo_env import build` → настоящий `Api` на демо-таблице;
- интерфейс — `python tools/demo/check.py studio|menu|constructor|audit` (скриншот + ошибки JS);
- синтаксис — `node --check frontend/script.js`, `python -m py_compile …`.
Ролики обучения после изменения интерфейса — скил `/tutorial-video`.
