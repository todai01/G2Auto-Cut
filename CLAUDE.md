# GVox (G2Auto-Cut)

Настольная программа для записи и подготовки голосовых фраз IVR (банк, RU/KZ):
запись по таблице с суфлёром, нарезка, эталоны сумм и дат, аудит, сдача.
Python-бэкенд + веб-интерфейс в окне pywebview (Windows, WebView2).

## Как работать с пользователем

- Пишем по-русски. Интерфейс — строгий, минималистичный, без лишнего текста.
- После каждого законченного изменения: коммит → пуш в рабочую ветку → отправить
  пользователю **только изменённые файлы** (SendUserFile). Зип всего проекта — только по
  просьбе: `git archive --format=zip --prefix=G2Auto-Cut/ -o <scratchpad>/G2Auto-Cut.zip HEAD`.
  Готовая последовательность — скил `/ship`.
- **JS-файлы (`frontend/*.js`) пользователь не может скачать по отдельности — отправлять их всегда одним zip** (пути внутри как в проекте,
  `zip <scratchpad>/js.zip frontend/script.js …`); остальные изменённые файлы — как обычно, отдельно.
- Честно говорить, что проверено: песочница / демо-проект / браузер — не то же самое, что
  Windows + pywebview + Audacity + микрофон. Так и писать.
- Не придумывать новую механику там, где есть рабочая: запись — только через суфлёр Студии.
- Данные пользователя конфиденциальны (банк): не просить логины/пароли, не тащить реальные
  тексты/пути в коммиты, ролики и примеры. ИБ банка согласует автоматизацию и голосовые модели.
- PR не создавать без просьбы. Идентификаторы моделей в коммиты/код не писать.

## Устройство

- `main.py` — класс `Api` из миксинов `core/*` (все методы доступны JS как `pywebview.api.<имя>`).
  Каждый вызов из JS идёт в своём потоке → общее состояние меняется из нескольких потоков.
- `frontend/index.html`, `script.js` (~10 тыс. строк, один файл), `style.css`, `tutorial.js` (+ `tutorial/*.webm`), `listen.js`.
  Оформление — `frontend/ios.css` (грузится после `style.css`): тёмная тема в стиле iOS — цвета-токены, заливки кнопок вместо рамок,
  окна с размытием, шапка Студии как панель навигации (перестановка через CSS `order`, разметка та же). Новые стили — туда;
  отключить слой — убрать `<link … ios.css>` в `index.html`.
  Поверх ios.css — `frontend/gtime.css` (грузится последним): внешний вид как у GTime (`shift_timer/ui/style.css`) — фон #0e1116, карточки #171b22 с тенью вместо рамок,
  кнопки «карточка-2 + тонкая линия», сегменты `.seg` (RU / KZ, «Фразы / Переменные»), радиусы 13 / 16, шрифт Segoe UI Variable, акценты GTime
  (синий #5b8cff, зелёный #34d399, красный #e5484d, жёлтый #fbbf24, бирюзовый #2dd4b0 — те же значения прописаны в style.css / ios.css / script.js / listen.js вместо прежних iOS-цветов).
  Только тёмная тема (светлой, как у GTime, нет). Цвета меняются токенами в `gtime.css`; отключить слой — убрать `<link … gtime.css>`. Отступ `body` 18+26 px → высоты экранов `calc(100vh - 44px)`.
  Главное меню — списком (`HOME_LIST = true` в `script.js`: `homeInit` / `homeRender`, стили `.home*` в `ios.css`): разделы — карточки,
  пункты — строки; данные и действия прежние (`RADIAL_CATS`, `RADIAL_ITEMS`, `radialRun` нажимает скрытые кнопки `.menu-grid`).
  Кольцо осталось в коде: `HOME_LIST = false` возвращает его.
  Старый рабочий экран (`stage2-workspace`, монтажный стол) из меню убран: пункты «Загрузить текст», «Резать сырой WAV»,
  «Настройки нарезки», «Открыть готовые чанки» закомментированы в `RADIAL_ITEMS.new` (кнопки — в скрытой `.menu-grid`),
  урок «Нарезка записи» убран, «Недавние» — только проекты Студии (`get_recent_projects`). Экран ещё открывают
  «Пакетная сборка» и «Готовая папка» («Переменные»).
  Python → JS: `webview.windows[0].evaluate_js(...)`, в Студии — `_tts_push(payload)` → `ttsProgress(p)`.
- Студия записи: `core/tts_flow.py` (состояние, дубли, ярусы, сборка, кэши),
  `core/tts_live.py` (запись, суфлёр, распознавание), `core/tts_synth.py` (синтез).
- Прослушка переменных: `core/listen_mode.py` + `frontend/listen.js` (папка записей → папка кусочков
  «Фразы_Переменные» с ru / kz, где отмечают начало и конец — пара своя на язык → таблица; запись ищется
  по имени, при папке с ru / kz — в своём языке; автосрезка по голосу `core/voice_trim.py` (вдох / шум
  по краям), шаблон срезки как в суфлёре — `.gvox_listen_tpl.json` в папке записей; Enter — сохранить и дальше;
  синтез голосом пресета через `_SynthWorker`). Запись ищется по названию, затем по числу из него (`listen_num`:
  «одно опоздание» / «бір рет» → `1.wav`), файлы синтеза — тоже числом (`listen_stem`). Таблица с колонками на двух
  языках — `table_names[ru|kz]`, тумблер RU / KZ меняет названия. Выбрали саму папку `ru` — берётся родитель
  (`listen_lang_root`). «⇄ не та запись» — `listen_swap`: записи двух строк меняются местами вместе с «_до_правок»
  и правкой (кнопка «Поменять местами», M; каждый файл остаётся в своей папке). Папки языка по имени: `ru_mark` / `kz_mark`
  (`listen_dir_lang`), без языка (`uni_mark`) — общая для обоих, своя папка языка — раньше общей. Число вместо названия
  (`listen_num_name`) — только без латиницы: «AUDI 80» остаётся «AUDI 80.wav». L — сменить вид на той же строке: RU → KZ → УНИВ (тумблер; УНИВ — только если папка разделена на ru / kz). Виды: RU и KZ — строки
  без универсалов, УНИВ — только универсалы (`_listen_kind`: нет цифр в названии и нет записи в папках ru / kz); `rows[i]["base"]` —
  номер строки в таблице, он сохраняется при смене вида. Счётчик по всей таблице — `listen_totals` (RU, KZ, УНИВ и «Всего»). Синтез: голос — из списка сервиса (`listen_voices`) или «по образцу» (`listen_set_voice(-1)`: вкладка клона,
  эталон — запись на экране с правкой, текст эталона — название строки). «Универсалы» — `listen_uni_move`: записи без цифр
  из папок ru и kz → `uni_mark` (общая для RU и KZ; одно имя в обеих — ru в общую, kz в `uni_mark/_дубли_kz`, они не сканируются).
  «Обзор» — `listen_overview`: таблица RU / KZ «есть / нет». «В Audacity» / «Из Audacity» — `listen_to_audacity` / `listen_from_audacity`
  (прежняя запись — `_до_правок/<имя>_до_audacity`). Флажок «автонастройка» (`auto_on`) выключает срезку по голосу и громкость при открытии записи; «Авто» (A) работает всегда. Аудит: дубли — только в папках одного языка (`_audit_same_lang`). Громкость имени — по громкости начала и конца (`_listen_ref_loud`, флажок «громкость по фразам»). Воспроизведение цепочки — `listen_play`: у каждого запуска свой временный файл и номер (последний запрос побеждает, прежний — `skip`; общий файл при параллельных вызовах рвал звук); срезанные «кратко» края — с микро-фейдом. Куски разной частоты (начало 48 кГц, переменная 16–24 кГц) приводятся `utils/wav_io.segment_to` / `segment_like` (FFT / scipy), НЕ pydub `set_frame_rate`: его линейная интерполяция оставляет металлический шум (≈ −20 дБ) — голос звучит «роботом». Цифровой блок в Прослушке (`listenKey`): NumPad 8 / 2 — темп +3% / −3%; 1 / 3 — выбрать левый / правый край дорожки (`lEd.edge`, `listenEdgeSet`; на волне край цветной со свечением и подписью, в панели кнопка «край» подсвечена, Esc снимает); 4 / 6 — сдвиг выбранного края влево / вправо на 10 мс (Shift — 50 мс; `listenEdgeStep`; серия нажатий — один шаг отмены, идущее воспроизведение перезапускается); NumPad 0 — как Space. Клик по дорожке (без перетаскивания) — `listenPlayAt` → `listen_play(…, seek_kind, seek_ms)`: звучит с этого места (`from` в ответе, головка стартует со сдвигом).
- Прослушка, режим «Фразы» (`listen_mode('phrase')`, переключатель «Фразы / Переменные» в шапке, пункт «Прослушка фраз» в меню «Новый проект»): два независимых сеанса `_ls()` (`_listen_sessions['var'|'phrase']`) — у каждого своя папка, таблица, позиция, язык. Фразы: папка записей (с `ru` / `kz` или без), таблица — лист с шапкой `<phrase[_ru|_kz]>` + `<name_phrase[_ru|_kz]>` либо без шапки (A — текст, B — название файла) — `_listen_read_phrases`; строки без названия или без текста пропускаются (`skipped`). Экран показывает `row["text"]` под названием, играет только запись (цепочки начало → имя → конец и универсалов нет: `data-lvar` скрыты CSS по `data-lmode="phrase"`), правка / «Сохранить» / `_до_правок` / синтез (текст — фраза) — те же.
- Студия — «только переменные»: таблица без листа фраз или с листом переменных (`<mark>` и т. п.), не названным
  в шапке фраз, читается; `tts_table_analysis` (что записано / новое) → выбор «Только переменные» (`tts_set_scope`,
  `st["vars_only"]`); свои начало и конец (аудиофайлы) для листа — `st["var_ctx"]`, подставляются в `_tts_var_chains`
  и `_tts_value_context`.
- «Сборка» Студии, Space (`ttsTogglePlay`): выделено мышью на волне внизу (`ttsEdSelRange`) или на дорожке «Дубль» с ярусами
  (`ttsTierSel`, `ttsTierSelStart`, синяя полоса `.tts-tiers__sel`; клик без протяжки снимает) — играет выделенное (`tts_play(i, a, b)`),
  нет выделения — дубль с начала. Выделение на экране одно: новое на одной волне снимает другое. Края выделения тянутся мышью:
  на волне внизу — `tlHit` → `seledge` (ручки рисуются в `ttsEditorDraw`, приоритет над краями клипа), на «Дубле» — `.tts-tiers__sel-h` → `ttsTierSelEdge`.
- «Забрать из Audacity» (`tts_take_from_audacity`): файл дубля перезаписывается и КАЖДЫЙ раз копия становится исходником дубля
  (`Записи/Audacity_<chunk>_<ns>.wav`, `raw` / `orig`, клипы сбрасываются) — волна «Сборки» рисуется из исходника; раньше со второго
  возврата звук был новый, а волна — старая.
- «Два языка в одной записи» — кнопка в «Сборке» на дубль строки переменных (`tts_take_bil`, `t["bil"]`): ярусы
  удваиваются (RU, KZ, `_tts_tier_unit`), границы ставят вручную; файлы — `Значения/<лист>/<кат>/ru/<значение>.wav`
  и `…/kz/…` (`_tts_tier_path`), общий файл — в корзину. Готовность и аудит принимают пару ru + kz (`_tts_lang_done`).
- «Папка переменных» (кнопка в Студии, `tts_import_vars` в `audit_fix.py`): папка с готовыми значениями (файл на значение,
  внутри могут быть `ru` и `kz`) → копии в `Значения/<лист>/<кат>/[ru|kz/]<значение>.wav`; строки таблицы, у которых нашлись все
  значения, — на ленту дублем из склеенных файлов (`tier_clips` по границам, `tier_write`), «Сборка» показывает их с началом
  и концом фразы. Начало и конец (`var_ctx`) сами не спрашиваются — выбираются чипом «начало и конец…».
- Дубль с ленты, перетащенный в карточку «Переменные» (`ttsVarDrop`): кусочек фразы с переменной — сохраняется как кусочек; любой
  другой — `tts_take_to_raw_vars`: сырым файлом в `Фразы_Переменные/<имя фразы | дубль_NNNN>.wav`, без вопросов (дальше — «Прослушка»,
  «Начало / конец»); дубль на ленте помечается «→ Перем.» (`t["raw_var"]`). Кнопка «Переменные» открывает окно со вкладкой «Сырые»
  (`_tts_raw_vars_list`: файлы `Фразы_Переменные`, не ставшие кусочками): ▶ и «В сборку» (`tts_raw_var_to_rail` — дубль на ленту без фразы: подрезать, назвать F, Enter). В «Сырых» файл отмечают «Начало» / «Конец» (`tts_raw_mark`, `st["raw_marks"]`); «Сборка переменной» —
  `tts_raw_assembly`: папка записей переменной (спрашивается один раз, `st["raw_var_folder"]`) → экран «Прослушки»
  (`listen_setup_assembly`: строки — файлы папки, пара начало/конец — на оба языка). Волны: ключи кэша — с inode и ctime
  (`_listen_stamp`, `_file_sig`), полоска цепочки перечитывается при каждой полной перерисовке. `tools/files_to_excel.py` — названия файлов папки → столбец Excel без расширения.
- Дубли не теряются: смена / перенос таблицы — дубли перепривязываются по строке и названию (не стираются); `tts_project.json` пишется через .tmp, а если дублей разом стало 0 или на 10+ меньше — прежний файл копируется в `_Кэш/tts_project_до_<время>_<N>.json` (`_tts_backup_state`, хранится 10). «Вернуть дубли (N)» на пустой ленте — `tts_restore_takes`: из резервной копии (с привязкой по названию), остальные файлы `Чанки` — дублями без фразы (`free_chunks` в `tts_state`).
- Аудит: `core/project_handler.py` (`_audit_studio`), действия — `core/audit_fix.py`. «Финальная папка» (`audit_final_folder`): `Финал_<дата>/Перманентные_<дата>/{ru,kz,без_языка}/` — язык фразы по слову `ru` / `kz` / `kk` в названии файла (`_audit_name_lang`) — и `Переменные_<дата>/`; папки создаются по мере файлов (нет переменных — папки «Переменные_…» нет; ничего не найдено — ошибка, пустой «Финал_…» не остаётся). Текст фразы в списке — крупный, только для чтения (выделяется и копируется, как и название файла); править текст в аудите нельзя (в режиме «по голосу» правка распознанного осталась).
- Классика: `phrase_handler.py` (Excel, нарезка), `variables_handler.py` (суммы, пакетная сборка),
  `constructor_handler.py` (конструктор), утилиты — `converter.py`, `clone_prep.py`,
  `filename_match_handler.py`, `table_to_pptx_handler.py`.
- Синтез по таблице (утилита): `core/batch_synth.py` + окно `#bsynthOverlay` — Excel (шапка `<firstname>`…) →
  каждое значение готовым голосом по одному с паузой (строка за строкой, слева направо), спрашивает с какой строки
  и сколько; файлы `Синтез_<таблица>/<столбец>/<значение>.wav`, повтор значения — копия в `<столбец>_повторы(_2…)/`; голоса и языки — `SYNTH_PRESET_VOICES`, `SYNTH_LANGS`.
- «Разбор записи сумм» (`core/raw_sums.py`, окно `#rsumOverlay`, пункт «Переменные» в меню): один длинный сырой дубль, прочитанный
  по свободной таблице (строка 1 — заголовки; блоки столбцов через пустой столбец; строка блока — фраза, ячейка — ярус; ячейка
  «тысяча / тысячи / тысяч» — конец яруса слева; опечатки чинятся по словарю чисел — `rs_canon`) → куски. Распознавание —
  large-v3-turbo в ОТДЕЛЬНОМ ПРОЦЕССЕ (`_rsum_bg` → `GVox.exe --rsum-worker job.json` / из исходников `python -c … rs_worker_main`):
  окно читает ход из `state.json` (`rs_apply_log`), стоп — файл `stop` (пачка дописывается), «Фон» (по умолчанию) — ядер на 2 меньше
  и BELOW_NORMAL_PRIORITY_CLASS (Студия и прослушка без заиканий), «Максимум» — все физ. ядра (`_rsum_threads`). Распознавание
  пишется по пачкам в `<кэш>.part` (`_rs_part_load`): после остановки / закрытия «Разобрать» продолжает с того же места.
  Нет модели в папке — по-старому, в процессе окна (слот KZ, скачать / указать папку). Несколько пачек сразу (num_workers)
  на Windows с процессором без быстрых int8-инструкций вышли в разы медленнее (×0,14 против ×0,4) — не используем.
  Связей со Студией и Прослушкой у разбора нет (сняты по просьбе); экран «Сборка сумм» тоже убран — дальше работа в Audacity («В Audacity»). Повторный проход модели по фразе (`find_alignment`, 30 с её работы)
  — только где он правит границы: в числах слово услышано не тем / запинка / слова нет / время схлопнулось (расхождение
  в начальной фразе — не повод); по ходу распознавания его не делаем (`RsCutter.live`, `fa_later`) — фразы уточняются одним
  заходом в конце (`_prefetch_fa`). Граница «начальная фраза → первое число» — самая длинная пауза до середины первого слова
  числа (`rs_longest_pause`): хвост «…сти» не уходит в кусок с числом. Сжимать паузы внутри окна и брать small для первого
  прохода пробовали — медленнее / хуже. Окна по паузам 4–12 с (`rs_windows`)
  склеены через 1 с тишины в пачки ≤ 27 с (`rs_packs`: модель всегда считает 30 с, так в 2–3 раза быстрее, а whisper пишет
  дословно — на сплошном длинном куске он выкидывает повторы и склеивает числа); «резиновое» слово > 1,6 с, в котором голоса больше,
  чем нужно на это слово (там спрятан пропущенный повтор; одна пауза — не повод), — его окно распознаётся заново отдельно,
  окно показывает «перепроверяю окно …». Выравнивание с фразами — `rs_align` (попытку можно бросить /
  повторить; последняя полная — основная, прочие — `_запасные/`, только уверенные); границы — время распознанных слов, а если
  распознанное не совпало с таблицей — whisper `find_alignment` по тексту фразы; «прилипание» к паузам, долгая пауза между
  словами — разрез по краям слов (`rs_cells_bounds`). Сохраняются только числовые ячейки (начальные фразы — нет), значение
  столбца — один раз (повторы «сто» после «девятьсот» и их запасные — нет). Неуверенные (распознано не то / внутри куска не то /
  конец не распознан / кусок длиннее обычного) — красные. Выход: `<запись>_куски[_N]/<столбец заголовок>/<текст>.wav`

  Тесты: `tests/test_shift_timer.py` (часы подменяются — `Clock`), `tests/shift_logic.test.js` (node). Exe — `.github/workflows/build-shift-timer.yml`,
  **только вручную** (workflow_dispatch) → Releases `gtime-N` (один `GTime.exe`); собирать по команде пользователя.

## Сборки exe

- `build-exe.yml` (всё + модели), `build-exe-lite.yml` (без распознавания) — на пуш; `build-exe-studio.yml` — только вручную:
  `build_exe.py --studio` (= `--no-asr` + `frontend/edition.js` → `GVOX_EDITION = 'studio'`): в меню только «Студия записи»
  и «Недавние» (`STUDIO_ONLY` в `homeItems`), Releases `gvox-studio-N`. В репозитории `edition.js` всегда `'full'`.

## Предметная область

- Таблица Студии: лист фраз (`<phrase>`, `<name_phrase>`, флаги `<start>/<start_2>/<end>`) и
  листы переменных `<sum_ru>`, `<sum_kz>`, `<date_ru>`… «Фраза с переменной» = кусочки
  start / start_2 / end вокруг значения.
- Папки проекта: `Проверенные/` (цельные фразы), `Фразы_Переменные/` (кусочки),
  `Значения/<лист>/<категория>/<значение>.wav` (эталоны: `Значения/sum_kz/million_kz/5.wav`),
  служебные: `Записи/`, `Чанки/`, `_Корзина/`, `_Кэш/`, `.gvox_undo/`.
- Суммы читаются строкой, режутся на ярусы. Логика 1: миллионы + сотни + тысячи + тенге.
  Логика 2: отвечает **только** за «сотни тысяч» (100…900, 9 строк).
- Казахский: тысячи всегда «<число> мың» (бір мың); месяцы в KZ-листе показываются по-казахски.
- Аудит смотрит только `Проверенные`, `Фразы_Переменные`, `Значения` (корзина — никогда).

## Грабли, на которые уже наступали

- Не менять общее `st["sum_logic"]` даже временно — поток записи прочитает чужую логику
  (см. `_tts_logic_now`, thread-local).
- Опрос из JS не должен накладываться (`ttsRecPoll` с флагом занятости); тяжёлое в
  `tts_prompt_info` — кэшировать (`_tts_claims_cache`, `_tts_ver`).
- Распознавание пишет числа цифрами — `spell_digits` перед сравнением.
- Временные файлы прослушки — в системный temp, не в папки проекта (аудит их увидит).
- Фон под ярусами — сквозной по строке (`_tts_tier_audio` поверх `_tts_tier_dry`).

## Агенты — только для больших задач

`.claude/agents/`: `gvox-search` (Haiku, поиск по коду без правок), `gvox-check` (Sonnet, проверка на
демо-проекте по сценарию), `gvox-clips` (Sonnet, переснять ролики обучения, в фоне).
Звать только на больших задачах (новый режим, переделка экрана, много файлов + ролики).
Мелкие и средние правки — самому в основной сессии: агент стартует с нуля, это дольше и дороже.
План, ключевой код, проверка отчётов агентов, коммит и пуш — всегда в основной сессии.
